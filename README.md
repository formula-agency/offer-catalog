# Каталог офферов

Откройте `index.html` в браузере. Просмотр каталога работает локально; интернет нужен только во время обновления данных Scout.

В каталог попадают только изображения из папок с названием `Обработанные`. Тип оффера, район и ЖК берутся из структуры папок, комнатность — из названия файла.

## Как добавить новые офферы

1. Положите готовое изображение в подходящую папку `Офферы Новостройки… / Тип / Район / ЖК / Обработанные` в одном из трёх наборов офферов.
2. Запустите `Обновить каталог.cmd`.
3. Обновите страницу в браузере.

Команда сначала запускает встроенный Windows OCR через `extract-offer-areas.ps1`, чтобы распознать площадь непосредственно на новых или изменённых баннерах. Затем `sync-scout-data.ps1` обновляет список изображений, безопасно получает Scout/Neopic, сохраняет публичные параметры квартир и заново формирует `offers-data.js`. Вручную редактировать файл данных не нужно. Для синхронизации требуется PowerShell 7 (`pwsh.exe`); OCR работает через штатный Windows PowerShell.

## Данные Scout

Scout сопоставляет оффер по двум параметрам: названию ЖК и общей площади. Сначала площадь берётся из названия вида `1+ 38,2 м²`; если её там нет, используется локальный OCR изображения. Результаты сохраняются в `offer-area-cache.json`, поэтому повторно распознаются только новые или изменённые баннеры. Проверенные вручную исключения для изображений, которые OCR не читает, хранятся отдельно в `offer-area-overrides.json`; значение не угадывается.

Токен можно задать локальным файлом `scout.env` в корне каталога либо пользовательской переменной окружения `SCOUT_TOKEN`. Для совместимости со спецификацией также поддерживаются имена `NEOPIC_TOKEN`, `SCOUT_API_TOKEN` и файл, содержащий только сам токен:

```text
SCOUT_TOKEN=полученный_токен
```

`scout.env` исключён из Git. Скрипт не выводит токен, не записывает его в `offers-data.js` и не передаёт браузеру. В репозиторий попадает только публичный кэш `scout-data.json` с ценой, этажом, домом, секцией, площадью, ценой за м² и полной историей изменений. Полный список кандидатов и причины несопоставления записываются локально в `scout-sync-report.json`; этот файл также исключён из Git.

Если Scout не передаёт необязательный публичный параметр, подтверждённое значение можно добавить в `scout-manual-overrides.json`. Ручное значение применяется только при отсутствии поля в API и сейчас используется для этажности дома ЖК «Горизонт» из выгрузки Scout.

Полные ответы API объёмные, поэтому на шесть часов сохраняются в локальной папке `.scout-cache`, исключённой из Git. Для принудительного получения свежих ответов используйте `pwsh -File .\sync-scout-data.ps1 -ForceScoutRefresh`.

Правило выбора соответствует `scout_apartment_integration_spec.md`: активные квартиры с точным совпадением ЖК и площади до 0,01 м², официальный источник, максимальная цена, затем `section DESC`, `floor DESC`, `source_id ASC`. Агрегаторы сохраняются только в техническом отчёте и не смешиваются с официальной ценой.

## Метка «Не актуально»

На каждой карточке и в окне просмотра есть кнопка `Не актуально`. Помеченный оффер сразу скрывается из общего каталога и переносится в отдельный раздел, где его можно вернуть в актуальные.

Метки сохраняются в браузере менеджера и не сбрасываются после запуска `Обновить каталог.cmd`. Если оффер удалён из папки `Обработанные`, его устаревшая метка автоматически очищается. Между разными браузерами и устройствами метки не синхронизируются.
