# Интеграция очереди каталога: состояние реализации

## Обследованный проект

Сайт — статический GitHub Pages без серверного API и без сборщика JavaScript. Страница использует `index.html`, `app.js`, `styles.css` и сгенерированный `offers-data.js`. Офферы исторически собираются PowerShell-скриптом из изображений в папках `Обработанные`; изображение скачивается обычной ссылкой на файл. Публикация настроена из корня ветки `agent/publish-offer-catalog` по адресу `https://formula-agency.github.io/offer-catalog/`.

Существующие поиск, выбор нескольких ЖК/районов/комнатностей, просмотр, скачивание, локальная отметка «Не актуально», Scout и плашка NEW сохраняются. Текущий массив `types` — ручные теги старых картинок. Он не является структурированным массивом вариантов покупки и не удовлетворяет контракту очереди.

В репозитории нет `AGENTS.md`, пакетного CI, исходников предкаталога и файлов отправщика, перечисленных в ТЗ. Локальный поиск также не нашёл `catalog-queue.js`, `queue-payload.cjs`, `catalog_queue_server.py`, `catalog-types.d.ts` и их тесты. Поэтому изменения отправщика подготовлены как общий контракт и точный перечень, но не встроены в отсутствующий проект.

27 октября 2026 года доступ через сервисный аккаунт `formula-otchet@otchety-493307.iam.gserviceaccount.com` проверен в режиме чтения. Таблица «Очередь для загрузки офферов в каталог Формулы» содержит единственный лист «Очередь сайта» (`sheetId: 0`), 26 столбцов сетки и 15 заполненных заголовков исходной схемы. В очереди обнаружено 6 строк со статусом `ready`; все шесть JSON разбираются и нормализуются, число вариантов покупки — от 1 до 7.

Девять технических столбцов ещё отсутствуют, поэтому рабочая очередь не готова к запуску загрузчика. Доступ к шести указанным в строках Drive-файлам не подтверждён: Drive API возвращает `404 notFound`, что для закрытого файла также означает отсутствие доступа у сервисного аккаунта. Ни один из шести ID очереди не сопоставился с прежними карточками сайта по точному URL источника или по паре ЖК + площадь; они рассматриваются как новые записи, пока заказчик не подтвердит обратное.

## Что реализовано локально

- JSON Schema v2 с квартирой, всеми вариантами, акциями, сроками, `imageRevision`, `sourceReview` и полями совместимости.
- Общий нормализатор v1 → v2, канонический JSON и SHA-256 `payloadVersion`.
- Валидация ID, дат, enum, чисел, уникальности вариантов и акций; ошибка одного варианта блокирует оффер.
- Публичная проекция без источника, статусов, квитанций, банка, расчётных входов и `sourceReview`. Существенные `stages` переходят в понятные ограничения; расчётный вариант получает только пометку происхождения.
- Чистое ядро фильтрации. Все финансовые ограничения и выбранные акции проверяются в одном варианте. Реализованы семейная категория «Любая», И по акциям, диапазоны, отделка, сроки в часовом поясе Екатеринбурга и отсутствие кэшбэка.
- Выбранный интерфейс «одна квартира — одна карточка»: первый подходящий вариант открывается автоматически, остальные доступны в переключателе; смена варианта обновляет суммы, ставку, сроки, акции и ограничения.
- Скачивание формирует производный PNG из исходного изображения оффера и текстового блока именно выбранного варианта. Исходник не изменяется и не называется отдельной планировкой.
- Загрузчик с claim по ID/версии/попытке, upsert полного снимка, явным reload UUID, повторной сверкой перед публикацией, глобальной блокировкой публикации и восстановлением квитанции из реестра.
- Адаптер Google Sheets по уникальным именам 24 управляемых столбцов. Это низкоуровневое представление; его разрешено использовать только за единым сервисом/блокировкой.
- Загрузка изображения через Drive API с проверкой MIME, размера и HTML-ответа. Путь изображения содержит SHA-256 содержимого, поэтому новая картинка не повреждает прежний релиз.
- Локальный издатель неизменяемых релизов: новый каталог активируется атомарным указателем только после проверки. Это тестовый механизм, не подтверждение публикации GitHub Pages.
- Чистые функции отправщика: новая версия возвращает строку в `ready`, неизменённый клик сохраняет статус и квитанции, явный повтор получает отдельный UUID.

Новый режим подключён через `queue-offers-data.js`. Пока в нём нет записей, сайт использует прежний `offers-data.js`; это позволяет тестировать новую очередь без удаления старого каталога. Рабочие данные очереди и рабочий деплой пока не подключены.

## Обязательные изменения в отсутствующем отправщике

1. В `snapshot`, типах, CSV/Sheets-проекции и восстановлении очереди пропустить без потерь `schemaVersion`, `imageRevision`, `sourceReview`, `ratePeriod`, `promotions` и `actionValidUntil`.
2. Использовать один нормализатор и тестовые векторы хеша с загрузчиком. Не вычислять версию из форматированного текста таблицы.
3. Изменить `plan_upsert`: искать строку по ID; одинаковую версию не трогать; новую версию записывать в ту же строку и ставить `ready`, сохраняя квитанцию последней публикации.
4. Добавить команду «Повторить загрузку»: новый `reloadRequestId`, кроме уже активной попытки той же версии.
5. Любые изменения строки выполнять через единый сервис очереди. Прямая независимая запись отправщика в Sheets оставляет гонку и не соответствует ТЗ.
6. Добавить 9 служебных столбцов справа, не удаляя 15 исходных и пользовательские столбцы. До записи проверять лимит ячейки JSON.
7. Не выводить акции из текста или низкой ставки. Не распространять подарок между вариантами без подтверждённой области действия.

## Необходимая конфигурация и доступы

Значения секретов в репозитории не хранятся. Для тестового подключения нужны:

- Google identity через `GOOGLE_APPLICATION_CREDENTIALS` либо Workload Identity;
- чтение таблицы и запись только управляемых статусов/квитанций;
- чтение выбранных файлов Drive;
- отдельная тестовая таблица или копия рабочего листа;
- тестовая ветка/репозиторий GitHub Pages и способ дождаться фактического deploy;
- защищённый токен публикации (`GITHUB_TOKEN` или эквивалент) вне клиентского кода;
- выбранное устойчивое хранилище блокировок/повторов, если сервис запускается более чем на одном хосте.

Конфигурационный шаблон находится в `config/catalog-loader.example.json`.

На текущем рабочем доступе чтение Sheets работает, а чтение выбранных Drive-файлов заблокировано. Перед тестовой загрузкой нужно предоставить этому же сервисному аккаунту доступ к самим файлам либо к общей папке, в которой они создаются.

## Миграция, запуск и откат

1. Сделать резервную копию таблицы и ветки сайта; сохранить текущий `offers-data.js`, изображения и commit SHA.
2. На копии таблицы проверить уникальные заголовки/ID и неизвестные статусы. Добавить 9 столбцов справа, не меняя порядок и содержимое существующих столбцов.
3. Рассчитать первые версии после нормализации. Не придумывать `uploadedVersion` для старых строк.
4. Заполнить и подтвердить карту `migration/legacy-offer-id-map.example.json`. Не объединять по одному совпадению ЖК, площади или цены.
5. Запустить синтетические тесты, затем загрузчик против тестовой таблицы и тестовой ветки. Проверить доступный URL и только после этого обратный `uploaded`.
6. Подключить выбранный интерфейс вариантов и выполнить браузерные сценарии на компьютере и телефоне.
7. После явного разрешения: повторить backup, применить миграцию рабочей таблицы, развернуть сервис очереди, выполнить ограниченную первую пачку и включить расписание 15 минут.

Откат: остановить расписание и ручные триггеры, запретить новые claims, вернуть Pages на сохранённый commit, восстановить таблицу из копии либо только 9 служебных столбцов по журналу миграции. Не удалять строки и старые изображения. После отката сверить опубликованный реестр с таблицей; строки без подтверждённой квитанции оставить для ручной сверки, а не объявлять загруженными.

До явного разрешения запрещены: изменение рабочей таблицы, push в ветку `agent/publish-offer-catalog`, включение расписания и публикация рабочего сайта.
