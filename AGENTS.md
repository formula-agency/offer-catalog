# Правила работы с каталогом офферов

Перед изменениями прочитайте `spec.md`, `README.md` и проверьте текущую ветку. Репозиторий содержит две разные линии: опубликованная статическая витрина и отдельная ветка интеграции очереди. Не считайте код ветки разработки уже работающим на публичном сайте.

- Сохраняйте пользовательские изменения и содержимое папок офферов. Не запускайте `reset-offer-catalog.ps1` без прямого поручения: он меняет состав публикации.
- В `offers-data.js` не правьте записи вручную: его создаёт `generate-offers-data.ps1`. Меняйте подтверждённый исходник, `offer-metadata.json` или явный override, затем пересобирайте данные.
- Публикуйте только готовые изображения из `Обработанные`. Не включайте исходные изображения из других папок, приватные ключи, `scout.env`, `Credentials/`, `.scout-cache/`, отчёты синхронизации или рабочие выгрузки.
- Не придумывайте цены, платежи, ставки, площади, сроки, названия ЖК и геометрию планировок. Не смешивайте условия разных вариантов покупки. Не называйте ремонт в подарок готовой отделкой.
- Для фирменных баннеров сохраняйте смысл и все читаемые цифры оригинала. Визуальные ориентиры и запреты — в `EDIT.MD`; цвета интерфейса — в `styles.css`. `EDIT.MD` является промптом/редакторским заданием, а не автоматическим генератором.
- Опубликованная витрина уже поддерживает несколько тегов у оффера, фильтр `NEW` и пересечение выбранных категорий по И. Это проверка тегов одного оффера, а не ещё не выкаченная проверка всех условий внутри одного варианта покупки из финального ТЗ.
- Перед публикацией проверяйте состав `git diff --cached`, отсутствие секретов и работоспособность сайта на широком и узком экране. Изменение ветки GitHub Pages немедленно влияет на публичную витрину; публикацию и миграцию данных согласовывайте отдельно.
- Код предкаталога, SVG-шаблон карточки, очередь Google Sheets и серверное приложение находятся в отдельном закрытом репозитории `digitalkindratlv-cell/catalog-formula`. Не копируйте их внутренние данные в этот публичный репозиторий.
